# Fast hybrid embedding retrieval

The primary entry point is `notebooks/fast_hybrid_embedding_retrieval_kaggle.ipynb`. It is generated by:

```bash
python scripts/build_fast_hybrid_embedding_notebook.py
```

The notebook defaults to `MODE="pilot"`, a deterministic stratified 80/20 term holdout. Use the pilot's `selected_blend.json` in `MODE="confirm"` to run five grouped folds for only the winning contrastive recipe. Use the confirmed JSON in `MODE="final"` to refit on all available positive terms, score submission pairs, and write a validated submission.

## CLIs

Build the frozen MiniLM/TF-IDF cache and its deterministic exact top-500 pools:

```bash
python src/hybrid_embedding_retrieval.py build-cache \
  --data-dir data \
  --cache-dir outputs/hybrid_embedding/frozen_cache \
  --device cuda
```

Mine the two negative files and build pilot slates:

```bash
python src/hybrid_embedding_retrieval.py mine-contrastive
python src/hybrid_embedding_retrieval.py mine-reranker
python src/hybrid_embedding_retrieval.py build-slates --mode pilot
```

Train and score the contrastive two-tower model:

```bash
python src/contrastive_biencoder.py train \
  --negative-pool outputs/hybrid_embedding/contrastive_negative_pool.csv \
  --split-manifest outputs/hybrid_embedding/pilot/split_manifest.csv \
  --outer-fold 0 \
  --cache-manifest outputs/hybrid_embedding/frozen_cache/manifest.json \
  --fp16

python src/contrastive_biencoder.py encode --entity items
python src/contrastive_biencoder.py score-pairs
```

Training uses a 10% grouped inner-term split only to select the epoch. It then restarts from the pretrained encoder and refits the selected number of epochs on every outer-training term. The outer holdout is never used for checkpoint selection.

## Main artifacts

- `frozen_cache/manifest.json`, FP16 embeddings, ID maps, TF-IDF matrices, and exact retrieval pools
- `contrastive_negative_pool.csv` and `.audit.json`
- `reranker_negatives.csv` and `.audit.json`
- `split_manifest.csv`, `hybrid_validation_slates.csv`, and `retrieval_metrics.json`
- contrastive checkpoint with shared transformer, both 256-dimensional heads, tokenizer, split/cache fingerprints, and training metrics
- `ablation_results.csv` and `selected_blend.json`
- final semantic scores, blend scores, submission CSV, and submission report

Both negative files retain `term_id,item_id`, so the existing CatBoost and LightGBM loaders can consume them directly.
